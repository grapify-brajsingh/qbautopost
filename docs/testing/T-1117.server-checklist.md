# T-1117 server checklist: dashboard on the office network

Tick each box on the QuickBooks server (and the accountant's PC where stated), in order. If a step does not match, stop,
write what you saw next to it, and do not go on. The agent verified the scripts statically and the API against fakes and a
throwaway PostgreSQL in Docker; `install-dashboard.ps1` has not been run on a real server. Background: `docs/runbook.md` section 11.

Do this with a recent QuickBooks backup and a copy of `C:\qb-autopost\`. Never write a password or key into this file.

## A. Before migrating

- [ ] **A1. Nothing uses the new field names.** Run as the owner, API stopped:
  `SELECT count(*) FROM saved_request_versions WHERE payload::text ~ '"(post|pushId|email)"';` prints `0`.
- [ ] **A2. Dry run.** `.\deploy\install-dashboard.ps1 -Source <dist> -WhatIf` prints the `Dry run:` line; no `dashboard.new` folder exists afterwards.

## B. Migrate and install

- [ ] **B1. Apply `DashboardV2` and `AuditEventsView`.** `.\deploy\apply-migrations.ps1` ends with `Schema is current` and
  counts both migrations; `grants.sql` ran (the app role has `SELECT` on `audit_events`, nothing more).
- [ ] **B2. Install.** `.\deploy\install-dashboard.ps1 -Source <dist>` prints `Installed ...`; `C:\qb-autopost\dashboard\index.html` exists.
- [ ] **B3. Second install keeps the old one.** Run it again: `dashboard.old` exists and `dashboard.new` does not.
- [ ] **B4. Settings.** `Api:Bind` is `https://0.0.0.0:5443`, `Api:Tls` is set, `Api:Cors:AllowedOrigins` is empty.
- [ ] **B5. Start** with `start-all.ps1`. If the dashboard folder was missing at the previous start, this restart picks it up;
  the log has no "dashboard not installed" warning.

## C. Network

- [ ] **C1. Firewall rule** exists: `Get-NetFirewallRule -DisplayName 'QbAutopost dashboard 5443' | Get-NetFirewallAddressFilter`
  shows `RemoteAddress LocalSubnet`, the port filter is TCP 5443, and the profile is Domain, Private only.
- [ ] **C2. Certificate is trusted** on the accountant's PC: opening `https://<server>:5443/` shows no certificate warning.
- [ ] **C3. Sign in from another PC** over HTTPS, and change the password if asked. **A reload keeps the session** (the refresh
  cookie path is `/api/v2/auth`); a deep link such as `/requests` reloads to the page.
- [ ] **C4. Unchanged API.** `GET /jobs` and `GET /health` return the API answers (JSON; `GET /jobs` is `401` without a key);
  `GET /api/v1/health` is as before. No HTML from any API path. No `Access-Control-*` header in the responses.

## D. Measure (Q-96)

- [ ] **D1. Time a 500-row add on a test company file** (never the live file): save a 500-row request, post it from the
  dashboard, and note the seconds from click to result: ______ s. If it takes longer than 60 s it ends `unknown` and
  nothing is posted twice. Record the number in `docs/tracker.md` Q-96; if it is over about 40 s, ask whether to raise
  `QuickBooks:BusyTimeoutSeconds`.
- [ ] **D2. Disconnect.** Start a post, close the browser tab: the request still finishes and records (check the audit feed).

## E. n8n

- [ ] **E1. Switch** the HTTP node to `POST /api/v2/saved-requests` with `email` `{subject, receivedUtc, from, messageId}`, a
  new UUID `pushId` per push, and `Idempotency-Key` = Message-ID. A test mail answers `201`; a replay of the same mail answers `200`.

## F. Rollback rehearsal

- [ ] **F1. `.\deploy\install-dashboard.ps1 -Rollback`** swaps the previous version in (`dashboard.failed` holds the one
  removed); the site still loads. Install again to return.
