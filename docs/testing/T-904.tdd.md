1. As the operator, when a connection is slow I want to know **whether it worked** — session 13 reported
   `quickbooks-busy` while the session had in fact succeeded behind a certificate dialog.

   a request queued behind another QuickBooks call.
3. As the operator, I want the first call of the day to survive the certificate dialog rather than be abandoned at the
   60 s busy timeout.
4. As the owner, I want a request that names its own company file refused outright (Q-50, Q-44) — and refused before
   anything is sent to QuickBooks.

## 4. Safety properties worth naming

- **A write can never get the longer timeout.** `ProcessWithTimeoutAsync` throws if the qbXML is not read-only, so
  FR-11's rule (a posting call keeps the busy timeout, because an abandoned write may already have been applied)
  cannot be widened later by reusing this path.
- **One lock.** The gateway is a single instance registered under both its interface and its concrete type. Two
  registrations would have produced two `SemaphoreSlim`s and allowed two SDK sessions to overlap.
- **The wait and the call share one budget.** A caller asking for 180 s means "I am willing to wait 180 s", whether
  the delay is another call ahead of it or QuickBooks itself.

## 5. Spec amendment and gaps

- **FR-A-4's step list was changed** from six illustrative steps to the three that are measurable. One gateway call is
  one SDK session, so `openConnection` / `beginSession` / `endSession` happen *inside* `hostQuery` and cannot be timed
  separately without widening `IQbGateway` — and doing that means COM code only the server can verify. Rather than
  emit invented numbers, the check reports what it measures; a slow phase still surfaces, because the whole
  `hostQuery` is marked slow and carries the hint. Raised as **Q-56**.
- **The 1 s wait-log threshold and the slow-step threshold are deliberately different numbers.** The log fires above
  1 s (an operator wants to know about any real queueing); the `slow:` hint fires above the busy timeout, which is the
  point at which the old code would have given up.
- **Not verified here:** that a real certificate dialog behaves as modelled — the 180 s default outlasting it, and the
  wait line appearing when a job holds the gateway. The fake reproduces the *shape* (a slow call that succeeds), not
  QuickBooks. This belongs on the same server visit as T-903.
- **No coverage number** — unchanged from T-901…T-903.
