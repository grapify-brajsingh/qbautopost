# T-1409 server checklist: scheduled QuickBooks list sync (spec A-10)

Tick each box on the QuickBooks server, in order. If a step does not match, stop, write what you saw next to it, and do
not go on. The agent verified the code against fakes (fake gateway, fake presence, a throwaway PostgreSQL); nothing here
has run against a real QuickBooks. Background: `docs/runbook.md` section 5.4, spec `docs/qb-list-sync-m14.md` sections 5,
6, 7, 10 and 15.

Use a **test company file** (never the live one) and a recent backup. Never write a key or password into this file.
The API and QuickBooks must run in the **same Windows session** (the signed-in desktop).

## A. Migrate and start

- [ ] **A1. Migrate.** `.\deploy\apply-migrations.ps1` ends with `Schema is current` and counts the `QbListSyncs` migration.
  The table `qb_list_syncs` exists.
- [ ] **A2. Start the API** (QuickBooks open on the test company). The startup log `QuickBooks:` line ends with
  `list sync every 30 min (first after 2 min), lists in the database`. Result: ______ .
- [ ] **A3. Interval for the test.** Set the machine variable `QuickBooks__ListSync__IntervalMinutes=5` and restart the API;
  the log now says `every 5 min`.

## B. QuickBooks open: an `ok` row

- [ ] **B1.** Wait for the first scheduled sync (2 minutes after start, then every 5). Run
  `SELECT * FROM qb_list_syncs ORDER BY id DESC LIMIT 5;` : a row with trigger `schedule`, outcome `ok`, and counts for
  accounts, vendors and customers. Counts: ______ .
- [ ] **B2.** `GET` the v2 QuickBooks lists (token with `requests:read`): `lastSync.outcome` is `ok` and `nextSyncUtc` is
  about 5 minutes after the sync. `GET /api/v1/health/ready` shows `qb-lists` ok with `lists from HH:mm` (UTC).
- [ ] **B3. Trimmed query accepted.** The row in B1 is `ok` (not `qb-status`), so QuickBooks accepted the list query with
  `IncludeRetElement` at qbXML 13.0 (`QuickBooks:QbXmlVersion`). Open `C:\qb-autopost\qb-audit\sync-lists.*.qbxml`: the
  request holds `IncludeRetElement` lines and the response holds names and types only. Edition and version of QuickBooks:
  ______ .

## C. QuickBooks closed: `skipped`, nothing started

- [ ] **C1.** Close QuickBooks completely (no `QBW.EXE` / `QBW32.EXE` in Task Manager, Details tab, all users).
- [ ] **C2.** Wait for the next scheduled sync. A row appears with outcome `skipped`, reason `quickbooks-not-open`; the log
  has one Warning for it. Result: ______ .
- [ ] **C3. No QuickBooks started.** After the skipped row, and again after one more interval, Task Manager still shows
  **no** `QBW.EXE`. Result: ______ .
- [ ] **C4. Lists kept.** The lists in the v2 `GET` are the old ones; `syncedUtc` is unchanged; `lastSync.outcome` is
  `skipped`; `qb-lists` readiness names `last sync skipped HH:mm (quickbooks-not-open)`.
- [ ] **C5. Presence in the API's session.** Open QuickBooks again in the API's session; the next sync is `ok` (this proves
  `QbPresence` sees QuickBooks there). If QuickBooks is open but every sync is still `skipped`, the API runs in another
  session: record the session id from the startup log (`Windows session`) and Task Manager's.

## D. A dialog open

- [ ] **D1.** In QuickBooks open a modal dialog (for example File > Open or Create Company, or a Write Checks window with an
  unsaved change prompt) and leave it. Wait for the next scheduled sync.
- [ ] **D2.** While it waits, submit a job (a dry run is enough). The job does not fail; note when it was submitted.
- [ ] **D3.** The sync's delay is at most about 2 minutes and is logged (Warning with the reason, or the Information line with
  the outcome). Close the dialog. The job submitted in D2 completes. Delay seen: ______ ; job finished: ______ .

## E. Sync now from the dashboard

- [ ] **E1. As an editor,** with QuickBooks open: press Sync now. The pickers update (a name added in QuickBooks a moment
  ago appears). A `qb_list_syncs` row with trigger `dashboard` and the user's id in `requested_by`.
- [ ] **E2. As a viewer:** no Sync now button; calling the sync route directly answers `403`.
- [ ] **E3. QuickBooks closed:** Sync now answers `409` `quickbooks-not-open` and the dashboard says so; still no `QBW.EXE`.

## F. Finish

- [ ] **F1.** Restore `QuickBooks__ListSync__IntervalMinutes` to the default (remove the variable, or `30`) and restart.
  To confirm the off switch, set it to `0`: the startup line says `list sync schedule off`, `nextSyncUtc` is null, no new
  scheduled rows appear. Restore it afterwards.
- [ ] **F2.** Write the result (pass, or what failed) in `docs/tracker.md` against T-1409 and set the row to `done`.
