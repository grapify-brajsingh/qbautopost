# T-911 — TDD evidence

**FR-A-14 transport · FR-A-15 rate limiting · FR-A-17 input hardening.** Three separable pieces, three RED/GREEN
cycles, one task. Branch `m9-api-v1`, 2026-09-23.

Until D-4 this app was safe because nothing off the server could reach it. Every requirement below exists because
that sentence stopped being true, so the question each test answers is not "does the feature work?" but "what does a
stranger get?".

---

## 1. User journeys

| Who | Wants | Gets after T-911 |
|---|---|---|
| The owner, deploying remotely | To expose the API to the ERP | The app **refuses to start** on a non-loopback bind without TLS, naming the setting that would allow it |
| An operator in a hurry | To get it working today | `Api:AllowInsecureRemote=true` works, warns at startup **and on every request**, so the shortcut cannot be forgotten |
| A caller integrating | To post transactions | 10 posts a minute, 120 other calls; a `429` carries `Retry-After` and says which limit was reached |
| Monitoring | To poll health | 600 a minute per address, and never blocked by somebody else's failed keys |
| Somebody guessing keys | To try a million | 10 tries a minute, then five minutes of `429` from that address |
| A caller with a mis-mapped field | To post a 1 MB memo | `400` naming the field and the bound, before any row is read |
| A remote caller probing paths | To name `C:\qb-autopost\logs` as a job folder | `400` naming `Paths:AllowedJobRoots`, and traversal is judged on the normalised path |

## 6. Test specification

**`TransportTests` (21).** Loopback binds start (`127.0.0.1`, `localhost`, `[::1]`); `0.0.0.0`, `*`, `+` and a real
address refuse without TLS, and refuse if *any* of several binds is remote; TLS or an explicit `AllowInsecureRemote`
lets them start, the latter with a warning; CORS `*` refuses while a named origin does not; a remote bind with an
empty `Paths:AllowedJobRoots` refuses; a `PfxPassword` from the settings file warns, names the file, and **does not
contain the password** (asserted), while one from the environment is silent; `CameFromFile` is tested against a real
JSON file and a real in-memory provider, because the warning is worth only as much as that detector; HSTS follows
TLS; `Require` throws; and the hardening headers are asserted on both a `200` and a `401`.

**`RateLimitTests` (19).** Bucket by effect — the four mutating routes of `ApiRoutes.IsIdempotent` (including
`POST /jobs`) are `Post`, everything under `/health*` is `Health` on both prefixes, the rest `Default`; the spec's
numbers 10/120/600; per-client overrides honoured for post and default, ignored for health; partition by caller not
address, with one caller sharing a budget across addresses and two callers never sharing one; buckets kept apart, so
spending the post budget still allows a read; host-level `429` with `Retry-After`; health limited per address; the
limiter genuinely inert when off; and the shipped default asserted to be **on**.

**`AuthBrakeTests` (8).** Under the limit admits, over it blocks for five minutes, only the guessing address is
blocked, the block expires, the count restarts with a new minute, `Retry-After` shrinks as the block runs down, a
success forgets the count, and end to end a repeated bad key turns `401` into `429`.

**`PathAllowListTests` (14, Core).** Inside, the root itself, outside, traversal out, traversal that stays in, a
prefix sibling (`jobs-archive` is not in `jobs`), relative paths, null/empty/blank, several roots, an all-blank list
(refused, not read as "everywhere"), and a configured trailing separator. Every path is built with `Path.Combine`
under a temp root so the file means the same thing on Linux — handoff trap 11, which is how T-908's guard shipped
broken.

**`InputLimitTests` (12, host).** Body over the cap is `413` and inside it is read; `memo` > 4096 and
`payee`/`account`/`lineAccount` > 255 are `400` naming the field, while exactly at the bound is not refused *for its
length*; a job folder outside the allow-list is `400` naming `Paths:AllowedJobRoots`, inside it is `202`, traversal
out of it is `400`, and with no allow-list configured any absolute folder is still accepted.

## 7. Decisions worth reading

1. **An empty `Paths:AllowedJobRoots` means "unconfigured", not "refuse everything" — but only on loopback.**
   FR-A-17 requires the allow-list and §12 ships it empty, which cannot both be honoured literally: enforcing an
   empty list refuses every job and no installation starts, while ignoring it is the permissive reading rule 4
   forbids once callers are remote. So startup **refuses a non-loopback bind with an empty list**, the same shape as
   the TLS rule. Today's loopback deployment is unaffected; the moment the owner exposes the port they must say where
   jobs live. Marked `// SPEC-GAP T-911`, recorded as **Q-63**.
2. **`POST /jobs` counts as posting** for rate limits, though its scope is `jobs:write` rather than `qb:post`. It
   reaches QuickBooks more slowly than a direct post, not less certainly, and the cheaper bucket is the one that
   would have to be defended later.
3. **The brake counts unrecognised keys only.** A `403` for a missing scope or a wrong network means the key *is*
   somebody's, so it is recorded as a success: otherwise a legitimate client could lock itself out of the API by
   polling one route it was never granted, which is a support call, not a defence.
4. **Over-long fields are `400` for the whole batch, not a held row.** A 4 KB memo is a caller whose mapping is
   wrong, and letting the other rows through would post money under a misunderstanding. Compare `amount-over-limit`,
   which *is* a held row — there the caller meant exactly what they said.
5. **The body cap is enforced twice** — Kestrel (production, at the socket) and `RequestSizeMiddleware` (in the app).
   The app-level one exists because Kestrel's limit is invisible to the test host, so a cap living only in
   `ConfigureKestrel` would be both untested and absent behind any other host.
6. **`Api:Tls:PfxPassword` is deliberately absent from `appsettings.json`** though §12 lists it. Shipping the key
   invites an operator to fill it in; the environment variable is named in the refusal message and in the warning
   instead.
7. **Case sensitivity follows the platform.** Comparing paths case-insensitively everywhere refuses nothing extra,
   but would accept `/SRV/Jobs` as `/srv/jobs` on a system where those are two different folders.

## 8. Known gaps — what this does **not** prove

1. **No TLS handshake has ever happened.** `TlsCertificate.Load` is executed by no test: the test host does not use
   Kestrel, and loading a PFX would mean shipping a certificate and a password into the repository. What is proven
   here is the *decision* to require TLS, not that Kestrel then serves it. **A person must verify TLS on the server**,
   with a real certificate, before the bind is moved off loopback.
2. **`AddServerHeader = false` is unverified on a real socket.** The header test asserts the response carries no
   `Server` header, but TestServer never adds one, so that assertion would pass even with the Kestrel line deleted.
   Only `curl -I` against the real host proves it.
3. **HSTS is never emitted in a test.** `UseHsts` is asserted as a decision (`TransportGuard.UseHsts`); the header
   itself appears only on an HTTPS request, which no test makes.
4. **Startup refusal is tested as a function, not as a process.** `TransportGuard.Require` throwing is asserted
   directly; that `Program.cs` calls it before a socket opens is read from the code, not executed — the same
   limitation `RequireApiKey` has carried since T-910.
5. **The rate limiter runs with the limits *tests* choose, not the shipped ones.** `ApiFactory` sets
   `Api:RateLimits:Enabled=false` (handoff trap 14) and the host tests use 1–2 per minute so they finish in
   milliseconds. That the shipped default is `Enabled=true` with 10/120/600 is asserted on the settings object, not
   by watching a real minute pass. **Nobody has seen the production numbers throttle anything.**
6. **A fixed window is a fixed window.** A caller may send 10 posts at 11:59:59 and 10 more at 12:00:00. FR-A-15
   specifies per-minute limits and this is the standard reading, but it is not a sliding window, and a determined
   caller gets 20 through in two seconds once a minute.
7. **The brake is per process and in memory.** A restart forgives every blocked address, and two instances behind a
   load balancer would each count separately. Deliberate, but a real limit on what the brake buys.
8. **`QuickBooks:AllowedCompanyFolders` is enforced but untested at the host level.** The check is wired into both
   company-file routes and `PathAllowList` is tested thoroughly in Core, but no host test names an overridden company
   file outside the list — the override is off by default, so such a test would have to turn it on first. The path
   logic is shared with the job-folder case, which *is* tested end to end.
9. **Nothing here has met a real QuickBooks.** As with T-907–T-910, every behaviour above was proven against
   `FakeQbGateway`, `FakeHermesClient` and `FakeQbSdkProbe`.
10. **The unexplained single failure of §5 is unexplained.** It is recorded, not resolved.
