# T-1707 server checklist: what the QuickBooks SDK does when the wrong company file is open

Tick each box on the QuickBooks server, in order. If a step does not match, stop, write what you saw next to it, and do
not go on. Write the HRESULT as hex (`0x…`, 8 digits), copy the message text exactly, and give times in seconds.
Never write a password or key into this file. Run with a recent QuickBooks backup, and use COPIES of the company files if
you can: nothing here posts, but QuickBooks is opened and closed several times.

The agent could not run any of this. T-1706 added `QbSessionErrors.WrongCompanyFile`, which is empty
(`// SPEC-GAP T-1707`): until you fill it in below, a failed `BeginSession` on another company's file is mapped to
`QuickBooksCompanyFileUnavailableException` (503 `company-file-unavailable`, never retried). Background: ADR-0013 and
`docs/multi-company-m17.md` section 4.7.

Per ruling B5, this checklist covers only SDK-level checks with the tools that exist today. Checks that need
`/api/v2/companies/{id}/check` or a posted statement are at the end under "Moved to T-1715".

## How to open one file (the probe used by every item)

The v1 endpoints open the file named by `Company:FilePath`. The `companyFile` request field of
`POST /api/v1/quickbooks/connection/test` is checked (`QuickBooks:AllowCompanyFileOverride`, `AllowedCompanyFolders`) but
the agent found that the session is still opened on `Company:FilePath`, so do not rely on it to open another file. To
probe file X:

1. Set `Company:FilePath` to X's full path in `C:\qb-autopost\appsettings.Production.json` (or the environment variable
   `QBAUTOPOST__Company__FilePath`) and restart the API. Name the file you used next to each item.
2. Run one of (the API key stays in `QBAUTOPOST__Api__ApiKey`, never typed into this file):
   - `.\scripts\qb-server-check.ps1 -Step health` (opens a session through `GET /api/v1/health/quickbooks`), or
   - `POST /api/v1/quickbooks/connection/test` with body `{"timeoutSeconds": 300}`; the answer lists each step with
     `ms`, and `totalMs`.
3. Read the result and the API log. A failed open is logged as
   `could not open a QuickBooks session for '<file>' (0x<HRESULT>: <message>); is QuickBooks running with the
   certificate accepted for <app>?`. The log also shows the trace lines `BeginSession on '<file>'` and `session open`.
   Copy the `0x…: …` part exactly.

Files used below: **A** = Takoma's `.qbw`, **B** = S & A's `.qbw`, **L** = the largest company file.

- [ ] **1. Two files approved.** As the QuickBooks admin, open A in QuickBooks, accept the *QbAutopost* certificate with
  "Yes, always; allow access even if QuickBooks is not running" and the login user; close the file and repeat for B (and
  for L if it is neither). Record the full paths: A ____ B ____ L ____
- [ ] **2. `BeginSession(B)` while A is open.** Open A in QuickBooks (leave it open, no dialog showing). Set
  `Company:FilePath` to B, restart the API, run the probe. Record:
  HRESULT `0x________`, message text ____, seconds to answer ____, and whether a dialog appeared in QuickBooks ____.
- [ ] **3. The reverse pair.** Close QuickBooks, open B, set `Company:FilePath` to A, restart, probe. Record:
  HRESULT `0x________`, message ____. Same HRESULT as item 2? yes / no
- [ ] **4. Can the wrong-file error be told apart?** Probe each of these (restart the API after each `Company:FilePath`
  change) and record HRESULT and message:
  (a) QuickBooks closed and a file never approved with "allow access even if QuickBooks is not running" (use a third
  file, or remove the app's permission in QuickBooks Preferences > Integrated Applications): `0x________` ____
  (b) a path that does not exist, e.g. `C:\nowhere\x.qbw`: `0x________` ____

  If the HRESULT of item 2 or 3 also appears in (a) to (d), write **NOT DISTINGUISHABLE** here: ____
- [ ] **5. Background open with QuickBooks closed.** Close QuickBooks completely (no `QBW32.EXE` in Task Manager). A
  must have been approved in item 1 "even if QuickBooks is not running". Set `Company:FilePath` to A, restart, probe with

  (seconds = ms / 1000) ____ and whether QuickBooks is now running in the background (`QBW32.EXE` in Task Manager, no

- [ ] **6. Largest file.** Repeat item 5 with L (QuickBooks closed again first). Record the file size ____ MB, the
  seconds from `BeginSession` to `session open` in the log ____ and `totalMs` ____. Compare with the current settings:
  `Api:SyncPostTimeoutSeconds` (default 120), `QuickBooks:BusyTimeoutSeconds` (default 60),
  `QuickBooks:ConnectionTestTimeoutSeconds` (default 180). Is the open time over any of them? ____
- [ ] **7. Can the open file be named?** (a) With A open in QuickBooks and `Company:FilePath` = A, call
  `POST /api/v1/quickbooks/connection/test` with `{"includeCompanyInfo": true}`: the `companyFile` in the answer is what
  `GetCurrentCompanyFileName` returns. Record it exactly (case, drive letter or UNC) ____ and whether it matches the

  (b) With A open, set `Company:FilePath` to B and probe (item 2): `GetCurrentCompanyFileName` needs the session ticket
  that a failed `BeginSession` does not return, so expect that the open file cannot be named. Write what the answer or

- [ ] **8. An approval dialog is pending.** Use a file never approved for QbAutopost (item 4a's file), first with
  QuickBooks closed, then open. Set `Company:FilePath`, restart, call the connection test with

  while the dialog was showing (does `BeginSession` block?) ____, after how many seconds ____ and with what message ____.
  Call it again during the wait: does the second call queue behind the first or fail at once? ____. Then answer or close
  the dialog and record the seconds until the first call returned ____ and whether the dialog was still showing after the
  API gave up ____.
- [ ] **9. Restore.** Set `Company:FilePath` back to the original value, restart the API, and confirm
  `.\scripts\qb-server-check.ps1 -Step health` is OK.

## What the developer changes afterwards (a follow-up commit under T-1707)

1. **HRESULT found and different from every item 4 case.** Add each `0x…` from items 2 and 3 to
   `QbSessionErrors.WrongCompanyFile` in `src/QbAutopost.QuickBooks/QbSessionErrors.cs` (as `unchecked((int)0x…)`),
   remove the `// SPEC-GAP T-1707` marker, and replace `Should_StartEmpty_When_NotYetVerifiedOnTheServer` with tests
   that the recorded HRESULTs map to `QuickBooksWrongCompanyException` and the item 4 HRESULTs still map to
   `QuickBooksCompanyFileUnavailableException`. Close Q-159 in `docs/tracker.md`.
2. **NOT DISTINGUISHABLE.** Leave the set empty; every targeted `BeginSession` failure stays
   `QuickBooksCompanyFileUnavailableException`; spec section 4.7 and ADR-0013 switch to `company-file-unavailable` only
   (no `company-file-open-elsewhere`); answer Q-159 with the recorded HRESULTs.
3. **Open file nameable after a failure (item 7b = yes).** Pass the name as `openFile` in the
   `QuickBooksWrongCompanyException` built by `QbSessionErrors.FromBeginSession` (it is `null` today).
4. **Open time (item 6).** If L's open time is above `QuickBooks:BusyTimeoutSeconds` or `Api:SyncPostTimeoutSeconds`,
   raise the setting in `appsettings.Production.json` and `docs/runbook.md`, and note it in the tracker.
5. **Item 5 failed** for an approved file: the "even if QuickBooks is not running" assumption of the M17 spec does not
   hold; raise it as a question in the tracker before T-1710 depends on it.
6. **Item 8 blocks.** Add the measured wait to the runbook note that tells the admin to answer the dialog (spec
   section 4.7, ADR-0013); change no lock rule.
7. **The `companyFile` field of the v1 connection test does not open that file** (found while writing this checklist).
   Record it as a tracker question; it is not changed here.

## Moved to T-1715

These need the v2 company check or a posted statement and are not part of this checklist:

- `POST /api/v2/companies/{id}/check` for S & A while Takoma is open (HRESULT in the API log line).
- Posting a Takoma statement with QuickBooks closed (background open on the real post path) and the time from the log.

- Wrong file open on a real post: refused as `company-file-open-elsewhere` (or `company-file-unavailable` per this
  checklist's result), nothing in either file, statement still pending, no retry in the log.
