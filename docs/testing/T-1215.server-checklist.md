# T-1215 server checklist: statement upload and the whole app on OpenRouter

Tick each box on the QuickBooks server (and the accountant's PC where stated), in order. If a step does not match, stop,
write what you saw next to it, and do not go on. The agent verified the code against a fake OpenRouter handler and a
throwaway PostgreSQL; nothing here has run against the real OpenRouter or a real QuickBooks. Background: `docs/runbook.md`
sections 2.4 and 12, spec `docs/dashboard-api-m12.md` sections 6.10, 8, 10, 14.

Use a **test company file** (never the live one) and a recent backup. Never write a key or password into this file.

**The sample PDF `D:\sample_payload\152_09_093026.pdf` is real client data. Never copy it into the repo, `tests\fixtures`,
or anywhere under `C:\qb-autopost`. Upload it from where it is, through the browser.**

## A. Migrate and configure

- [ ] **A1. Build and publish on Windows** (the ICU rule depends on the build OS). The server is Windows 10 1903+ / Server 2019+.
- [ ] **A2. Migrate.** `.\deploy\apply-migrations.ps1` ends with `Schema is current`; the new migrations (extraction records,
  `saved_requests` upload columns, posted-time index) are counted.
- [ ] **A3. Set the key and switches** as machine variables (runbook 12.1): `OpenRouter__ApiKey`, `OpenRouter__Enabled=true`,
  `Extraction__Enabled=true`. Outbound HTTPS to `openrouter.ai` is allowed. Restart the API.
- [ ] **A4. Startup log** shows `OpenRouter:` with key `set`, and **no** warning about `Asia/Kolkata` (Q-112). The key does
  not appear anywhere in the log.
- [ ] **A5. Health.** Signed in, `GET /api/v2/health` shows `extraction: configured` (token with `requests:read` or `health:read`).
