## 1. User journeys

1. As the owner, I want to know that the file QuickBooks has open **is** the file this app is configured to post into,
   before a batch goes anywhere near it.
2. As the operator, I want the answer without anything being posted, and without a qbXML request being sent at all.
3. As the operator, I want a stale backup reported — but I do not want this call to be the thing that decides posting
   is allowed; FR-11 keeps that decision.
4. As the owner, I want a request that names its own company file refused, as on the connection test (Q-50).

## 4. Decisions

- **`openInQuickBooks` is an error, `backupFreshness` a warning.** The first is the misconfiguration that posts a
  batch into another company's books; the second is a reason to be careful that FR-11 already enforces at post time.
- **The backup check calls `BackupGuard`**, the same code FR-11 uses to refuse a post. A second implementation could
  drift, and then "validate says fine, post refuses" — or worse, the reverse.
- **Short-circuit on an unusable path.** With no path, or a path that is not an absolute `.QBW`, the later checks
  would be reporting on something that cannot be the company file, so they are not reported at all rather than
  reported as passing.

## 5. Known gaps

- **FR-A-5's `companyName` check is not implemented.** It needs a `CompanyQueryRq`, which this app has never sent:
  no builder, no parser, no golden file, and no way to confirm the response element names against a real SDK from
  here. Guessing them would be a rule-4 violation, so it is **Q-57**. `openInQuickBooks` already answers the
  dangerous form of the question by comparing the actual file path, which is stricter than a display name.
- **`requireBackup` in the request body is accepted but not yet honoured** — the backup check always runs, since it is
  a warning either way. Worth removing from the contract if the owner does not want it.
- **Not verified here:** that the SDK's spelling of the open company file path matches the configured one on the real
  server (UNC versus mapped drive, for instance). The comparison normalises case and trailing separators; a UNC-versus-
  drive-letter difference would still read as "a different file". This belongs on the T-903 server visit.
- **No coverage number** — unchanged from T-901…T-904.
