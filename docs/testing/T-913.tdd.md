# T-913 — TDD evidence

**FR-A-18 (API reference exposure) and api-v1 §11.6 (the drift test).**
Session 18, branch `m9-api-v1`, 2026-09-23.

What this task had to make true:

- `GET /api/v1/openapi.json` serves a **hand-authored** OpenAPI document (.NET 8 has no generator, Swashbuckle is
  excluded), and a **drift test** fails the build when that document and the real route table disagree;
- `GET /api/v1/reference` renders it with **Scalar**, behind `Api:Reference:Enabled` (shipped **false**), with the
  "send request" buttons off (`AllowTryIt`, false) and the assets served from the package, not a CDN (`UseCdn`, false);
- the document declares the security scheme and the scope every operation needs, so the page is also the scope
  reference.

---

## 1. User journeys

1. **An integrator is handed a key and a host name.** They open `/api/v1/reference`, read what each route does, see
   under each one the scope their key must carry, and copy the request shape. Nothing on that page can post.
2. **Someone adds a route and forgets the document.** `dotnet test` fails on
   `Should_DocumentEveryMappedRoute_When_TheDocumentIsComparedWithTheRoutes`, naming the method and path. The
   hand-authored file cannot quietly go stale; that was the whole objection to hand-authoring it.
3. **The owner's server has no outbound internet.** The page still renders, because the script is served from this
   host out of the package's embedded copy.

that claim cannot drift either. `bearerAuth` stays declared, with its status written into its description.

## 6. Test specification

**`OpenApiDriftTests` (13)** — the document is fetched over HTTP from the host, so what is checked is what a caller
would read, not a file on disk. Every mapped `/api/v1` route has a documented operation; every documented operation
has a mapped route; every operation has a non-blank `summary`; every operation has a 2xx response with a schema under
some media type; every operation's `x-required-scope` **equals `ApiRoutes.ScopeFor`** for that method and path;
`bearerAuth` is declared as `http`/`bearer`; the scheme the document *offers* is `apiKeyAuth` in the header named
`ApiSettings.KeyHeader`; an operation declares `security: []` exactly when `ScopeFor` returns null (that is, for
`/health` and `/health/ready` and nothing else); the document is served with `application/json` when the reference is
enabled and **404** when it is not; a key without `health:read` gets 403 and one with it gets 200; and
`ReferenceSettings` ships disabled.

Route enumeration walks `EndpointDataSource` and normalises two things: a trailing slash (`/api/v1/jobs/` is
`/api/v1/jobs`) and a trailing optional parameter (`/api/v1/reference/{documentName?}` also answers
`/api/v1/reference`). Scalar's asset sub-paths under the reference prefix are skipped — an asset is not an operation.

**`ReferenceUiTests` (12)** — 404 when disabled; 200 `text/html` when enabled; the page's source URL resolves to
`/api/v1/openapi.json`; no `src`/`href` in the page points at another host; `GET …/reference/scalar.js` is answered
here with a real bundle; 403 without `health:read` and 401 with no key; and, as pure functions on `ScalarOptions`:
`AllowTryIt` false hides both request buttons and true shows them, `UseCdn` false leaves `BundleUrl` empty and turns
Scalar's telemetry and default (remote) fonts off, `UseCdn` true sets `BundleUrl` to the one CDN constant, and the
shipped settings have try-it and the CDN off.

## 7. Decisions worth reading

1. **The document is offered under the scheme that works.** FR-A-18 says "declares the security scheme
   (`Authorization: Bearer`)"; the app accepts only `X-Api-Key`. Declaring only bearer would have documented a
   fiction. Both are declared, `apiKeyAuth` is the one every operation is secured with, and **Q-67** asks the owner
   whether the middleware should learn `Authorization: Bearer` (a T-910-shaped change, not a T-913 one).
2. **The reference needs `health:read` in every environment** (SPEC-GAP T-913, **Q-66**). api-v1 qualifies that
   requirement with "in Production". `ApiRoutes.ScopeFor` is a pure function of method and path with no environment
   in it, and the stricter reading is the one rule 4 asks for. The cost is written down in Q-66: because the key
   travels in a header, **the page cannot be opened in a plain browser at all** — with or without this decision, in
   Production — so it is read today with a client that can set a header.
3. **Disabled means not mapped.** With `Api:Reference:Enabled` false the routes do not exist, so the answer is a
   plain 404 rather than a 403 that confirms there is an API explorer here to come back for.
4. **`x-required-scope` is asserted equal to what the middleware enforces**, not merely present. A document that
   *has* a scope field is worth very little; one that cannot disagree with `ScopeFor` is the scope reference FR-A-18
   asks for.
5. **Telemetry and the default fonts are off unconditionally**, not under `UseCdn`. Both reach a third party from the
   reader's browser; an operator who turns `UseCdn` on is asking for the script bundle, not for a usage ping and a
   font request.
6. **The document lives in `wwwroot` but is served by a mapped endpoint**, not by `UseStaticFiles`. Static files are
   served before the key check, which would have put the whole API surface — every route, every scope, every request
   shape — outside authentication. The endpoint also lets `Api:Reference:Enabled` govern both routes in one place.
   `Content Update … CopyToOutputDirectory` puts the file beside the executable, because the content root on the
   server is `AppContext.BaseDirectory` (api-v1 §12).
7. **`ApiRoutes` answers the fifth route question** (`IsReference`), as the handoff predicted, rather than a new
   place: `ScopeFor` and the drift test both need it and they must agree.
8. **Response schemas are honest but not exhaustive.** Where a body is large and already has a stable shape
   (`JobView`'s `held`/`skipped`/`posted`), the schema says `object` rather than inventing a field list that would
   drift silently — nothing checks those against the C# records. See §8.3.

## 8. Known gaps — what this does **not** prove

1. **No browser has ever opened this page.** Everything here is HTTP and string assertions. That the Scalar bundle
   renders, that the sidebar lists the operations, and that the page is usable at all are unproven. The one piece of
   browser behaviour that is checked — how the relative document URL resolves — is checked by *reproducing* the
   library's own line in C#, not by running it.
2. **The reference has never been opened by a person who had to authenticate.** Because the key is a header, a plain
   browser cannot fetch the page or its script. Nobody has yet confirmed which client the owner would use (see Q-66).
3. **The schemas are checked for existence, not for truth.** The drift test proves every operation *has* a success
   schema; nothing compares a schema's properties with the C# record that actually serialises. A renamed field would
   pass. The field names here were read off the records by hand on 2026-09-23.
4. **The documented failure statuses are not verified.** `400`, `409`, `502`, `503` and the rest are documented from
   the spec and the endpoint code; the drift test never asserts that a route can actually produce them.
5. **`UseCdn: true` has never been exercised.** The only test is that the option carries the constant. No request has
   been made to jsdelivr, deliberately — a test must not reach the internet.
6. **`Api:Reference:Enabled` is never true in a shipped configuration**, and no test starts the app in the
   Development environment, so "`appsettings.Development.json` turns it on" is asserted by reading the file, not by
   running it.
7. **The document has never been validated by an OpenAPI validator.** It parses as JSON and Scalar is handed it; no
   tool has checked it against the 3.0.3 schema. A `$ref` typo inside `components` would be found by a reader, not by
   this suite.
8. **Nothing here has run against a real QuickBooks**, which remains true of all of T-907…T-913.
